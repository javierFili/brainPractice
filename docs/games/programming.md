# Programming games

Ten games in the `programming` category (`src/games/programming/`, registered in
`src/games/programming/index.ts` in catalog order). All are untimed or generously timed, use
`feedback: 'explain'`, and recommend themselves to `programmers` (plus `teens` / `adults`).

Generated pseudocode is only ever run by the in-house interpreter (`src/domain/pseudocode`); no game
evaluates JavaScript built from content. Answers are computed by running the interpreter or a graph
solver, candidates that are ambiguous are rejected with `retryGeneration`, and number options use
`rankedNumericOptions` (answer rank uniform). Each game has `describeGameContract`, an independent
oracle across levels and seeds, progression checks (`expectNonDecreasing`) and guessability
measurements.

## Shared helpers

- `shared/content/`: `compile`, `runQuick` (no trace, tight step budget for searches), `runTraced`,
  `narrate` / `traceChanges` (step-by-step explanations from the trace), `numberChoice`
  (number options with uniform answer rank), `DraftOf`.
- `shared/ui/`: `ProgramPanel` (CodeBlock that scrolls inside its own box at 360 px, plus the
  trace in review) and `TraceTable` (re-runs the program with the interpreter after answering).

## Limitations

- Conditional Logic inputs come from a fixed grid (x, y in 0–9, optional flag); "reachable"
  means reachable within that grid. Labels are neutral letters (A–E) so meaning never hints at
  the branch.
- The interpreter has no `break`, so Loop Prediction's early exits use `return` inside a function
  or a compound `while` condition.
- Dependency Ordering uses real-world-ish task names chosen to imply no order; the instructions
  say only listed needs count, but some players may still bring priors. Level 1 "start first" is
  a warm-up: the task that needs nothing is visible in the list.
- Algorithm Construction's ordering list shows multi-line loop blocks on one line
  (`for i in range(3): x = x * 2`); the content view shows them formatted. The spare block is
  answered by moving it to the end, because the shared ordering format has no "unused" slot.
- Variable Tracking avoids list aliasing (the interpreter shares lists between names but this is
  not covered by its tests); "copies" are value copies of numbers.
- Generation stays under 5 ms on average per challenge in the tests, but the interpreter costs a
  few microseconds per run, so the searches (input grids, block orders) are the main cost;
  Algorithm Construction is kept to at most six blocks for that reason.
- Variable Tracking reports to `memory`, Loop Prediction to `patterns`, the other three to
  `logic`.
